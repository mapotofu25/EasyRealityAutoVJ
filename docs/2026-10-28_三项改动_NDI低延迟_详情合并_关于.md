# 2026-10-28 三项改动：NDI 低延迟开关 / 曲目信息与详情合并 / 关于内容

## 1. NDI 输出：最终只保留一个选项

**经过两轮沟通后的结论**：
- 先做过「开关一下低延迟」，再做过「本机一路 + 局域网一路（两个独立发送端）」；
- 但实测证明：**NDI 即使同机也走 TCP 回环（127.0.0.1:59xx）**，发送端分不分路都改变不了
  这一层编解码 + 网络栈开销 ⇒ 拆两路只是多一份编码，收益不成立；
- 用户拍板 **改回一个选项** ⇒ 双路实现已整体收回，代码回到「单一 NDI 发送端、SDK 默认时钟节流」。

现在界面上只有 **「NDI 输出」** 一个勾选框（括号说明文字已去掉）。
配置里也只剩 `output.ndi_enabled`（`ndi_lan` 已删除）。

**本机想要更低延迟的正确做法**：用 **Spout**（共享内存/GPU 纹理，不编码、不过网络栈），
NDI 留给局域网里的其他机器。

## 2.「此曲目信息」与「歌曲详情…」合并成一个入口

- 曲库右键（单选本机曲目）现在只有 **「曲目信息与详情…」** 一项，打开详情页时
  在顶部多一块**只读、可选中复制**的曲目信息（文件 / 歌名 / 艺人 / 曲风 / 曲风来源 /
  时长 / 采样率 / 指纹 ID / 完整路径）。
- 文本**只有一份真源**：`music_detail.info_text(cfg, path)`。
  `ui_main.show_music_info()` 也改调它（码表派生行、导入包里的歌仍然只有轻量弹窗，
  因为本机没有文件、打不开波形详情）。
- 不传 `info_text` 时详情页与原来完全一致（兼容 erlib 侧的同源实现与旧调用）。
