# ERAVJ RC4（2026.11.08）

> Easy Reality AutoVJ —— Windows 免费开源的自动 VJ 软件。
> 本版相对 RC3 的主要变化：**自动段落全面重做**（8 拍乐句对齐）、**图层行高可压到 38**、
> **BPM 双行显示**、**体积大幅瘦身**、**第三方署名全面校正**。

---

## 一、自动段落（本版工作量最大的一块）

一首歌「哪里是 drop、哪里是过渡」现在由 7 道 pass 依次判定，目标是让段落边界落在
32 拍（4 小节）的乐句线上。全库 89 首验收：**「8 拍奇数倍段」从 233 段降到 105 段，
变坏 0 首、新增碎段 0、接缝 0**。

新增 / 重做的 pass：

| pass | 作用 |
|---|---|
| `_align_transition_and_climax` | 连续 low 过渡链与高潮段对齐 |
| `_shift_odd_chain` | 整条边界链整体偏 8 拍时整块平移 |
| `_rebuild_after_false_climax` | 「假高潮 8 拍」之后的 drop 链按假高潮结束点重新起算 |
| `_regularize_phrase_lengths` | 局部窗口内把 8 拍奇数倍段规整成 16 拍整数倍；支持 ±8 双向解 |
| `_snap_weak_boundary` | 两侧一样响、听不出来的假边界，挪一格到 32 拍格上 |
| `_relocate_weak_boundary` | 边界落在「八拍台阶≈0」的地方而真台阶在别处 ⇒ 搬过去 |
| `_insert_break_transition` | 被并进大段的独立 8/16 拍过渡切出来，后链按 32 拍重铺 |

另外修掉的老问题：
- `_quantize_phrases` 只允许落在「16 拍 = 偶数小节」，导致全曲段落都在奇数小节时整体偏 8 拍
- `phrase_phase` 原来只在 {0, 4} 里二选一 ⇒「八拍切分偏一拍」
- 时长预算没有强档保护 ⇒ 漏掉真正的段落起点
- 合并短段时没有保留「更强的边界」
- `_odd_bars()` 的浮点容差（恰好 24 拍的段因 `t/tbl = 23.9987` 全被漏判）

**边界工整性自证**：任何一刀动手之后，整首的「8 拍奇数倍段」条数不许变多，否则整刀拒绝。

## 二、界面

- **图层行高下限 56 → 38**：行高 < 56 时图层头自动切「紧凑档」（按钮 20→16 高、间距收窄），
  保证 2×2 田字格按钮不被裁、整行高度真的跟着行高走。7 档几何实测：行高==格子高、
  按钮底边 < 头底边、58 及以上各档头高与改动前逐像素一致。
- **BPM 显示拆成「原曲 BPM + 变速倍率」**：变速不变调时也跟真实听感走（对齐 KVJ 的做法）。
- **详情页**：删「吸附：拍/小节」，改为「按 BPM 重新分段」；删「八拍相位翻转」入口
  （老配置里的 `grid_flip` 仍然生效）。
- **修「8 拍的线偏移 4 拍」**：`grid_flip` 以前只有引擎读、波形不读，同一首歌两处差
  1.655 s；现在由 `effective_grid()` 统一下发，引擎与波形同源。
- 段落文字挪进柱区内部，不再压住时间轴。
- 曲库列表 5 列表格（封面 / 标题 / BPM / 时长 / 来源），列宽可拖，右键「打开文件所在位置」。

## 三、认歌 / BPM

- 认歌校验照 KDJ 公开的三条判据重做：**得分 / 最弱窗 / 领先**（挡「重复段落的另一处」与
  「两段对一段错」）。
- **变速认歌**：长窗回退 + 斜率拟合 + BPM 变速档；`chroma` 12 音级能量相关估倍率；
  票数门槛全灭时的 chroma 冷启动。
- BPM 判据改跨段命中率；多 BPM 段自动识别；扫描 vs Beat This 交叉校验（仅 2× 歧义改判）。
- **离线 BPM 锚点**（`bpm_anchor.py`）：实时 BPM 分不出来时改按离线值走。
- 高 BPM（190~220）三处门控、低 BPM（70~115）锁定门控 + 半速修正；长曲分析崩溃修好。

## 四、码表 / 曲库

- 码表导出原子化（不再在导出目录留 `-wal` / `-shm`）。
- 码表转场不再用素材自身几何（修「缩小图淡出变全屏」「滑动从屏幕最右边进来」）。
- 「相邻同设置视为一个素材」：GIF 吸附紧挨时不再先切出再切入。
- 码表两端契约审计 + 名称统一 + 删除二次确认。
- 导入判重补上指纹对比；修 `song_id` / `src_path` 不同步导致的「重扫一次重复一行」。
- ERLIB：重新分析勾选曲目 + 二次确认；详情页恢复试听。

## 五、性能 / 体积

- 调色与后处理共用一次全画布读回/写回；胶片颗粒换更快的随机数生成器
  （1280×720 / 30fps 实测：本进程 19~22% → **12~14%**）。
- 打包排除 librosa / numba / llvmlite（省 115 MB）、NDI SDK 变体（63 MB）。

## 六、删除的功能（2026-10-30 大砍刀）

素材标签也不再自动生成。留着的「动态分」改由画面自身的运动量算。

- 补充说明：发行包静态打包了 **mutagen（GPL-2.0-or-later）**，二进制发行包整体按
  GPL-2.0-or-later 分发；**源代码仍为 MIT**。

## 已知限制

- 同一录音在曲库与导入库各存一份时，锁定到的 song_id 可能是另一份。
- 导入曲库与本地文件的对账仍依赖文件名，重命名会失配。
- 段落判定在「能量完全平坦」的段落上仍可能出现 3 小节 / 5 小节这种非标准乐句。
- 少数歌的段落边界仍会落在奇数小节上（105 段 / 89 首）。
