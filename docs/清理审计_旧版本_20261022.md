## 二、拟删除清单

### A. 构建输出 `dist_*`（32 个，每个 ≈759 MB）

- 证据：`tools/build_exe.py:32-33` 每次构建都用 `--workpath BUILD_ROOT --distpath DIST_ROOT` **重新生成**；`dist_*` 只是产物，不是输入。
- 唯一被“默认值”引用的：`tools/_realtest_lag.py`、`_realtest_latency.py`（默认 `dist_r38`）、`_rec_bench.py`（默认 `dist_rc1`）—— 都是**开发期一次性测试脚本**，删后需用 `AUTOVJ_DIST=xxx` 指定新目录，不影响产品与发行包。

**保留**：`dist_lat2`（10-22 最新一次构建，759 MB）—— 方便随时跑冒烟；其余 31 个可删：


### B. 构建中间目录 `build_*`（31 个）+ 默认 `build/`（合计 ≈1.0 GB）

- 证据：PyInstaller `--workpath` 产物（`build_<名字>`），含 `.spec`、`warn-*.txt`、临时收集的 DLL；构建可重建。
- 保留：无（**全部可删**）。若想保留最近一次的 spec 作为参考，可留 `build_lat2`（33 MB）。
- 另：根目录还有默认工作目录 `build/`（30 MB，`tools/build_exe.py:13` 的 `AUTOVJ_BUILD` 默认值），
  下次构建会自动重建，也可一并删除。

## 四、版本定义与依赖核对

### 1）版本号：**只有一处真源，无重复定义**

| 文件 | 角色 |
|---|---|
| `src/version.py` | 唯一手写定义：`APP_CHANNEL="RC2"`、`APP_VERSION=BUILD_VER+"-RC2"` |
| `src/_build_ver.py` | **自动生成**（`tools/build_version.py:106` 写入 `BUILD_VER`），每次打包覆盖，**不可手改、不能删** |
| `tools/build_version.py` | 生成器本身 |

`grep APP_VERSION=/BUILD_VER=/APP_CHANNEL=` 全库只命中上述三处 ⇒ **不存在“重复版本定义”**。

### 2）依赖版本：**没有过时钉死**

- 唯一的依赖清单 `requirements.txt` **完全不钉版本**：`PySide6>=6.8 / numpy / soundcard / opencv-python / soundfile / av / glfw`
- 实际安装：**av 18.1.0、PySide6 6.11.2、numpy 2.5.3**
- 全库 `grep "av==|PySide6==|numpy==|pyinstaller=="` **0 命中** ⇒ 没有“引用了不存在/过时版本”的条目可删。
- 建议（非清理项）：若要复现构建，把 `av==18.1.0`、`PySide6==6.11.2`、`numpy==2.5.3` 写进 requirements（Cue 端已钉 av）。

## 五、建议的删除方式

1. **先移后删**（可逆）：
   ```
   mkdir <项目根>\AutoVJ\_trash_20261022
   move dist_rc1 _trash_20261022\   （逐个或脚本批量）
   ```
2. 确认软件、测试、打包都正常后，再清空 `_trash_20261022`。
3. 不要动 `dist_lat2`（保留的那一个），否则冒烟脚本要重新构建。

> 提醒：P 盘“删除”在本机会先进回收站，**不立即释放空间**；要真正腾出 25 GB，需要清空回收站。

## 六、一句话答案

可安全清理的是 **32 个 `dist_*`（留 1 个）+ 31 个 `build_*` + 9 项旧备份/测试料 ≈ 25.3 GB**；
`_asio_sdk` / `_build_tools` / `_glenv` / `assets/models` / `_build_ver.py` 虽然“看起来像垃圾”，
但分别被构建脚本、运行代码和版本机制**真实依赖**，删了会坏，必须保留。
