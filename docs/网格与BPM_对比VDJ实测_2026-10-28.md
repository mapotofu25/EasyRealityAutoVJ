# 本地网格/BPM 算法 vs VirtualDJ（实测 50 首）

样本 = 曲库里 `grid.src == "vdj"` 的 50 首（VDJ 给了 BPM + 锚点，当标准答案）。
方法 = 对每首跑 `beatgrid.analyze_track()`（**不给任何 hint**，纯自算），与 VDJ 比。

## 结果

| 指标 | 改前 | **改后** |
|---|---|---|
| BPM 完全对（±1%） | 46/50 = 92% | **48/50 = 96%** |
| 小节相位（4 拍，±0.5 拍） | 41/50 = 82% | **43/50 = 86%** |
| 乐句相位（8 拍，±0.5 拍） | 36/50 = 72% | **37/50 = 74%** |
| 相位偏差分布（拍） | {0:44, 1:4, 2:2} | {0:45, 1:4, 2:1} |

## 改了什么

**① 交叉校验 BPM（关键）**：原来 `Beat This!` 的 BPM 会**覆盖** `scan_bpm` 的结果。
实测 `scan_bpm` 的 top-1 大多是对的（Extra Pain 99.40 / DeepSleep 175.00 / Floating Globe 140.00），
是 Beat This 把它们改坏（99.4→199.7、175→179.9）。
现在：**只在「两者正好差 2×」且扫描的折叠分数更高时**才改判，其余保持 Beat This 的结论。

> ⚠ 试过"谁分高信谁"：整体从 46/50 掉到 44/50 —— 因为多数歌 Beat This 的 BPM 本来就是对的。
> ⇒ 只在有硬证据的那一种歧义上动手。

**② 倍速消歧（`octave_fix`）**：用「奇偶拍槽能量比」判断是否被估成 2×。
⚠ 实测这条**区分度不足**（错的 0.80~0.84，对的 0.92~1.02），单独用不可靠；
真正起作用的是 ①，`octave_fix` 保留但只作为 ① 不成立时的旁证。

**③ 多窗投票（`analyze_vote`）**：实现了但**默认关闭**。
实测整体更差（BPM 48→42、小节 43→36、乐句 37→32）—— 短窗的小节相位不如整段，
投票把好的也拉低了。代码保留，可用 `vote=True` 显式开启。

## 与工业界对齐的一条经验

**半速/倍速没有一个 DJ 软件敢全自动判**：
- Mixxx（开源）提供 `beats_adjust_halve` / `beats_adjust_double` 两个**按钮**；
- Traktor 有 Grid 面板让 DJ 手动改；
- VDJ 的 `Phase` 本身就是可由用户调整的字段。

所以详情页也补了一组**整段微调按钮**：`−1 小节 / +1 小节 / −1 拍 / +1 拍 / ÷2 BPM / ×2 BPM`，
对应那 7 首「正好差 4 拍」的乐句歧义——纯音频解不了，就给人一键翻。
