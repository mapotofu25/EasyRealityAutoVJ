**一句话**：把配色从「逐列占比归一 + γ=2.4」改成「**各路独立映射** + β 压缩 + γ=1.05」，
混色列占比 **1.7% → 60.3%**、8×8×8 色格 **64 → 475**；幅度动态范围同步优化（均值 **0.687 → 0.486**），
观感从「近纯色竖条」变成「粉/橙/黄绿/青/蓝紫的连续混色层次」。

## 二、根因核实（team-lead 判断 ✅ 成立）

team-lead 指出「那套映射从数学上就不产生混色」——**核实成立**，并精确到代码：

改动前 `_colors` 做的是 **逐列占比归一**（`r+g+b≈1`）+ `c**2.4`：
```python
shares = rel / rel.sum(1, keepdims=True)   # ★ 逐列"此消彼长"：三路必然互相竞争
emph   = shares ** 2.4                      # ★ 再把微小占比推向 0/1
out    = emph / emph.sum(1, keepdims=True)  # ★ 再归一，仍是"和=1"
```
- **逐列占比归一**：一列里三路之和恒为 1 ⇒ **在数学上排斥"两三个频段同时亮"** ⇒ 天然无混色。
- **γ=2.4**：在占比之上再放大差异 ⇒ 主导通道被推到≈1、其余≈0 ⇒ **纯红/纯绿/纯蓝**。

两件事叠加，必然得到「99.7% 近纯色」。**根因确认**。

## 三、新映射方式与理由

### 3.1 配色：`_colors`（核心改动）

```
每路（低→R / 中→G / 高→B）**各自独立**：
  1) base = clip(E_band / ref_band, 0, 1)      # ref = 该路整轨 90% 分位（robust 归一）
  2) v    = base ** 0.55                        # β 压缩：抬升弱段
  3) v    = v ** 1.05                           # γ 温和强调（仅轻微拉开对比）
★ 不做逐列占比归一；各路保持自身亮度 ⇒ 多路可同时亮 ⇒ 自然混色/彩虹
★ 频段下限保护：ref 钉在 max(ref)*1e-3，防"把数值噪声归一成亮色"（纯音不串色）
```

**为什么这样能出混色/彩虹**：独立映射下，一列里三路互不争夺亮度，
于是「红+绿=黄、绿+蓝=青、红+蓝=品红、三路同亮=偏白/粉」自然出现 ——
正好构成 粉→红→橙→黄绿→青→蓝紫 的连续色轮，与用户给的参考截图同一路数。

**参数取值（实测标定，非拍脑袋）**：

| 参数 | 取值 | 理由 |
|---|---|---|
| `COLOR_REF_PCT` | 90 | 每路相对整轨分位归一；90 分位兼顾"抗单尖峰"与灵敏度。实测：90→mix 60%、95→50%、80→74%，取 90 平衡 |
| `COLOR_BETA` | 0.55 | β<1 抬升弱段，让弱频段也参与混色（β=1→mix 降到 29%、β=0.35→82% 但过灰） |
| `GAMMA` | 1.05 | **大幅下调**（原 2.4）。独立映射下 γ 只需轻微拉开对比；实测 γ 1.0→1.6 使 mix 68%→42%，取 1.05 兼顾对比与混色 |
| `REF_FLOOR_REL` | 1e-3 | 下限保护，纯音其它两路≈0 ⇒ 保持纯色（**保判据 3**）。实测纯音 100Hz→r=1、1kHz→g=1、6kHz→b=1 |

### 3.2 幅度：`_amp_columns`（解决"一堵墙"）

```
an  = clip(amp / P99, 0, 1)                # 全局分位归一
env = movavg(an, 1s)                        # 局部能量包络
loc = clip(an / (env + 0.12), 0, 1)        # 局部对比
pw  = 1.0 + 0.60 * env                      # ★ 随局部能量自适应
af  = an**pw * loc**0.30
```

**为什么自适应**（team-lead 建议的落地）：`pw` 随局部能量包络走 ——
**弱段**（env 小）→ `pw≈1`（几乎不压，**保持可见**）；**持续高能量区**（env 大）→ `pw` 升到 ~1.4（**加强对比、不糊成一片**）。
实测：固定 `an**1.4` 的弱段 p10=0.153；自适应把弱段抬到 p10=0.182，同时均值仍是 0.486（不再是一堵墙）。

## 七、兼容性说明（接线侧不受影响）

- `WaveformData` 字段 **`columns / amp / r / g / b / duration_sec`** 与类型**完全不变**（已用 `dataclasses.fields` 校验）。
- `compute(path, columns=None, progress=None)`、`load_or_compute(...)`、`cache_path_for(...)` **签名不变**。
- `r/g/b` 语义微调：**从"逐列占比(和为1)"改为"各路独立 0..1"**（这正是混色的来源）。
  接线侧只需把 `r/g/b` 直接当 0..1 通道上色即可，**无需任何改动**。
- ★ **缓存版本号 `CACHE_VERSION` 1 → 2**：配色算法变了，旧 `.npz` 缓存会给出旧颜色，
  故递增版本号让旧缓存**自动失效重算**（否则用户会看到"改了没效果"）。
