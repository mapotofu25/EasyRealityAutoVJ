## 2. 数据模型规格

### 2.1 `.ercue` 包结构（zip）

```
my_track.ercue (zip, ZIP_DEFLATED, compresslevel=6)
├── cuesheet.json     编排主数据（必需）
├── media/            可选：内嵌素材（embed=True 时才有）
│   └── <name>
└── thumbs/           可选：缩略图（设计文档提到，实际实现未写）
```
常量：`EXT=".ercue"`、`JSON_NAME="cuesheet.json"`、`MEDIA_DIR="media"`、`THUMB_DIR="thumbs"`（`cuesheet.py:33-36`）。

**读取容错**（`cuesheet.py:482-518`）：若不是 zip，可当**裸 JSON** 读；zip 里没有 `cuesheet.json` 就找第一个顶层 `*.json`；JSON 不是合法 JSON → 抛 `ValueError("码表内容不是合法 JSON：…")`。

**写包**（`save:543-579`）：先 `recompute_features()`；默认 `embed=False`（**只写清单，包几 KB**）；写包时用 `media_paths` 给缺失的 media 补 `sha256`/`name`/`embedded`。

**`Identity.meta_key` 归一化规则**（`cuesheet.py:172-182`，**必须照抄**）：
```python
def nz(s):
    s = (s or "").lower().strip()
    s = re.sub(r"[\(\[（【].*?[\)\]）】]", "", s)                 # 去括号后缀
    s = re.sub(r"\b(feat|ft|remix|vip|edit|mix|version)\b.*$", "", s)
    s = re.sub(r"[^0-9a-z\u4e00-\u9fff]+", "", s)                # 只留 数字/小写字母/汉字
    return s
return "%s|%s|%d" % (nz(artist), nz(title), int(round(dur/2.0)*2))   # 时长取整到 2 秒
```

| 字段 | 类型 | 含义 / 取值域 | 备注 |
|---|---|---|---|

| `src_in_sec` | float | ★ 素材入点（秒），默认 0 | **引擎从未支持 seek，UI 也未暴露**（见 §7） |
| `src_out_sec` | float \| null | 出点；None = 到素材末尾 | 同上，未支持 |
| `speed` | float | 变速，钳位 **0.1~3.0** | 缺省 1.0 |
| `crop` | list[4] \| null | `[x, y, w, h]` 归一化 0~1；长度不为 4 会被清成 None | |
| `xform` | object | `{"scale":1.0, "x":0.0, "y":0.0}`（x/y 单位是**百分比**，预览里 `/100*W`） | |
| `trans_in` | str | 入场类型，见 `TRANSITIONS` | 非法值回落 "fade" |
| `trans_in_beats` | float | 入场时长（拍），默认 2.0 | |
| `trans_out` | str | 出场类型 | |
| `trans_out_beats` | float | 出场时长（拍），默认 2.0 | |
| `snap` | str | `off/beat/bar/phrase`，默认 "bar" | 仅记录意图 |
| `note` | str | 备注 | |

`normalized()`（`cuesheet.py:113-126`）**必须在每次导入/编辑后调用**：
- `trans_in/out` 不在 `TRANSITIONS` → 改成 "fade"
- `snap` 不在 `SNAP_MODES` → 改成 "off"
- `speed` 钳到 0.1~3.0；`at_beats` ≥0；`end_beats` ≥ `at_beats`
- `crop` 长度 ≠ 4 → 清 None

## 3. 格式版本与兼容策略

### 3.1 三个版本号（`cuesheet.py:31-32`）

- `FORMAT_VERSION = 1`（当前支持的最高格式版本）
- `MIN_FORMAT_VERSION = 1`（能读的最低格式版本）
- ⚠ **绝不能拿程序版本号当格式版本**（`cuesheet.py:15` 注释原文：每次发版都会把旧码表误判成旧格式）。

### 3.2 导入时的判定顺序与**提示文案原文**（`capability_report:441-461`）

**按顺序**，且**一律不阻断导入**：

1. `format_version > FORMAT_VERSION` →
   > *"这张码表来自更新版本的工具（格式 v%d，本版支持到 v%d），部分内容可能读不到；已尽力按 v%d 读取。"*
2. `min_app_version > app_version`（且 `app_version` 非空）→
   > *"这张码表要求 %s 以上版本（当前 %s），部分画面可能不对。"*
3. `requires_features` 里有不在 `SUPPORTED_FEATURES` 的名字 →
   > *"这张码表用到以下本版没有的能力，将被忽略：%s"*（用「、」连接并排序）
4. 缺素材 → *"有 %d 个素材没找到。"*

返回 `(warnings: list[str], missing: list[str])`。

> ⚠ `capability_report` 的字符串是**面向用户的动态文案**，原项目要求接 UI 时必须 `setProperty("_i18nDynamic", True)` 并补 i18n 词条——**新项目若不做双语可忽略此约定**。

### 3.3 能力词表（`cuesheet.py:39-51`）

`SUPPORTED_FEATURES`（**本版实现**的 7 个）：
```
layer_multi   码表内多层
clip_fade     淡入淡出
clip_inout    素材入/出点
clip_speed    变速
clip_crop     画面裁切
video_embed   内嵌素材
```

`KNOWN_FEATURES`（已知但不实现，**只增不删**）= 上面 7 个 + `trans_glitch`、`trans_zoom`、`multi_layer_cue`、`remote_source`。

> ⚠ 设计文档 §4.3 的词表与此**不完全一致**（文档写了 `trans_glitch`/`trans_zoom`/`remote_source` 为 v1 词表成员，但代码把它们归入 KNOWN 而非 SUPPORTED）。**以代码为准**。

## 4. 认歌匹配（**实现是 4 级，不是 3 级**）

> 设计文档 §6 写的是"三级匹配（指纹→元数据→文件名）"，但代码最终实现为 **4 级**，
> 因为**跨机器时"名+艺人+时长"会因时长差 >2 秒必然命不中**（用户 2026-09-28 提出的关键疑问）。
> 证据：`cuesheet.py:237-292` 的 `match_track`，注释 `240-251`。

### 4.1 `CueSheet.match_track(title, artist, duration_sec, fp_id, file_name) → (TrackEntry|None, 命中级别字符串)`

逐级降级，越可靠越优先：

| 级 | 命中级别 | 输入 | 归一化 / 阈值 | 失败后 |
|---|---|---|---|---|
| ① | `"fingerprint"` | `fp_id` | 与 `identity.fp_id` 字符串相等 | 降级 |
| ② | `"meta"` | title + artist + duration | 用 `Identity.meta_key`（**时长取整到 2 秒**） | 降级 |
| ③ | `"title+artist"` | title + artist（**忽略时长**） | 见下 `_norm` | 降级 |
| ④ | `"file"` | file_name | 去扩展名 + `_norm` | 返回 `(None, "")` |

第 ③ 级的唯一性规则（`275-285`）：
- 命中 **恰好 1 个** → `"title+artist"`
- 命中 **多个** → 若 `duration_sec > 0`，取 `|时长差| 最小` 的，级别仍 `"title+artist"`；否则取第一个，级别 `"title+artist?"`（带问号，表示"没把握"）

第 ③/④ 级用的 `_norm`（`cuesheet.py:254-259`，**与 meta_key 略有不同，多去扩展名与 master/remaster**）：
```python
def _norm(s):
    s = (s or "").lower().strip()
    s = re.sub(r"\.[a-z0-9]{2,5}$", "", s)                    # 去扩展名
    s = re.sub(r"[\(\[（【].*?[\)\]）】]", "", s)              # 去括号后缀
    s = re.sub(r"\b(feat|ft|remix|vip|edit|mix|version|master|remaster)\b.*$", "", s)
    return re.sub(r"[^0-9a-z\u4e00-\u9fff]+", "", s)
```

### 4.2 `track_by_identity()`（旧接口，`225-235`）
只做 ① fp_id → ② meta_key 两级，**没有** ③④。`engine.set_cue_sheet` 用它（`engine.py:2235`）。
**新项目应统一用 `match_track`。**

### 4.3 认歌触发的自动切曲目（引擎侧，`engine._cuesheet_autoswitch:2326-2377`）
- 只在码表有 ≥2 首曲目时工作
- 输入 `snap["recognized_song_id"]`（来自 `ChargeBarEngine` 漏桶状态机），用它去 `_song_genre_lookup` 查 `{title, artist, path}`，再走 `match_track`
- **不自己加回滞/冷却**：状态机已做（充 10 票 + 每拍推进连续 + 偏移锁 ±0.35s + 槽内不满格才换）⇒ sid 一变即"已确认换歌"
- ⚠ **匹配失败时不要提交 `_cue_sid`**（`2354-2356`），否则这首歌首次没匹配上后永不重试（审查"严重-4a"）

### 4.4 指纹兜底给位置（`engine._cue_pos_from_fingerprint:2379-2405`）
- 门槛：`recognized_votes ≥ 40`（`CUE_FP_POS_MIN_VOTES`）、`recognized_offset ≥ 0`、结果年龄 `age = perf_counter() - recognized_t ≤ 3.0s`（`CUE_FP_POS_MAX_AGE`）
- ⚠ `recognized_t` 是 **perf_counter 不是 epoch**（混用会得到天文数字）
- 位置外推：`pos_sec = off + age × max(0.05, rate)`，再 `/beat_len`

> ⚠ **位置来源的优先级在开发中翻转过**：最初「设备权威、指纹兜底」；`_patch_fp_primary_sec.py` 改成「**这一版不接设备，指纹优先**」。新项目只做编辑，**位置源仅用于模拟走带**，这层可以不移植。

## 5. 交互规则（时间轴 `CueTimeline`）

### 5.1 滚轮语义（`wheelEvent:246-273`）

| 操作 | 行为 | 细节 |
|---|---|---|
| 水平滚轮（无修饰键） | 左右平移 | `_pan_beats(-dx/120 × max(1,view_beats) × 0.08)` |
| 滚轮（无修饰） | 上下滚动 | `_set_voff(v_off - n×54)`（n=deltaY/120） |
| `Shift`+滚轮 | 左右平移 | `_pan_beats(-n × max(1,view_beats) × 0.08)` |
| `Ctrl`+滚轮 | **以鼠标所在拍位为锚缩放** | `span = clamp(view_beats × 0.82^n, 2.0, 20000.0)`；`view0 = anchor - frac×span`（frac = 锚在视口里的相对位置） |
| `Alt`+滚轮 | 轨道行高 | `row_h = clamp(row_h × 1.08^n, 18.0, 90.0)`，然后重算 voff 钳位 |

### 5.2 鼠标拖拽（`mousePressEvent:460-484` / `mouseMoveEvent:488-515` / `mouseReleaseEvent:517-549`）

- **平移**：中键拖动，或**空白处左键拖动**（`_hit` 未命中 item）→ 记 `_pan=(x0,y0,view0,v_off,moved)`，光标变 `ClosedHandCursor`。拖动时 `view0 = max(0, v0 - dx/pxb)`（往右拖=时间往前）、`v_off` 同步。
- **拖 cue 改位置**：命中 item → 记 `_drag={lyr_id,item,row,dx,moved}`。移动中：`nb=_beats(x+dx)` → `snapped=_snap(it,nb)` → `_preview_dx`（只画预览偏移，不改数据）。`|_preview_dx|>1.0` 才算 moved。
- **跨层拖拽**：拖动中每次 `_hit` 拿 `row2`，变了就更新 `_drop_row` 并标 moved。松手时若 `_drop_row` 与源层不同 → 发 `layer_moved` 信号。
- **松手落点用 `_last_mx`**（最后鼠标 x），不是 `e.position()`（`517-528`）——因为跨层拖动松手位置可能不在 item 上。
- ⚠ 详见 §6.6 的三个相关坑。

### 5.3 吸附档位（两处，**单位不同，别混**）

- `CueTimeline._snap`（`451-458`）：按**拍**网格，`{"beat":1.0, "bar":4.0, "phrase":8.0}`，off 不吸附。
  - 注释 `453`：审查 M1 —— 旧数值把"小节"错写成 0.5 拍。
- `CueSheetEditor._snap_beats`（`1093-1096`，**静态**）：`{"off":0.25, "beat":1.0, "bar":4.0, "phrase":8.0}`。
  - ⚠ off 档在两处**语义不一致**：一个完全不吸，一个吸到 0.25 拍。

### 5.4 命中测试（`_hit:429-449`）
- `y < RULER_H` → 无命中
- 行号 `i = int((y - RULER_H + v_off) // row_h)`，越界或无 layer → 无命中
- 遍历该层 items，item 的 x 范围 `[x0-2, x1+2]` 命中（`x1` 用 `end_beats` 或"下一个 item 起点或视口右端"）
- 返回 `(layer, item|null, row)`；命中层但没命中 item → 返回 `(layer, None, row)`

### 5.5 标尺自适应（★ 用户明确要求过「缩小时上面的排数不要全部显示」）

`_ruler_plan(pxs) → (step_sec, line_sec, show_label, show_bar_mark, show_phrase_mark, show_beat_tick)`（`407-426`，**静态方法，便于自测**）：

- `pxs` = **每秒像素** = `(W-GUTTER)/view_beats × beat_len`
- `step_sec`：从 `(1,2,5,10,15,30,60,120,300,600)` 里取**第一个**满足 `cand × pxs ≥ 34` 的（数字按 `mm:ss` 排，需要 34px；`_fix_two_tests.py` 把阈值从 30 改到 34）
- `line_sec`：从 `(1,2,5,10,15,30,60,300,600)` 取第一个满足 `cand × pxs ≥ 2.0` 的（否则整屏条纹）
- `show_label = step_sec × pxs ≥ 34`
- `show_bar_mark = pxs × 2.0 ≥ 7`（● 小节标记）
- `show_phrase_mark = pxs × 4.0 ≥ 7`（◆ 乐句标记，8 拍）
- `show_beat_tick = pxs ≥ 6.0`（普通拍短刻度）

绘制（`paintEvent:276-405`）：
- **时间轴主刻度 = 整秒**（`sec0..sec1`）；`s % line_sec == 0` 画长竖线，否则画短刻度；`s % step_sec == 0` 画 `mm:ss`
- 拍/小节/乐句线：仅在 `pxs ≥ 2.0` 时叠加；`k % 4 == 0` 才算小节；`k % 8 == 0` 是乐句（◆ 橙色 `#c08a2a`），否则 ● 灰
- 轨道只画视口内的（`r.bottom()<RULER_H or r.top()>height` 跳过）
- 右侧细滚动条（当 `_max_voff>0`）
- 播放头红色 `#ff4d4d` 2px 竖线

### 5.6 坐标换算
`_x(beats) = GUTTER + (beats - view0)/view_beats × (W-GUTTER)`（`212-214`）
`_beats(x) = view0 + (x-GUTTER)/(W-GUTTER) × view_beats`（`216-218`）
常量：`GUTTER=74`（层名列宽）、`RULER_H=24`、`ROW_H=34`（`54-56`）
`TRACK_COLORS` 8 色循环（`52-53`）：`#378ADD #1D9E75 #D85A30 #7F77DD #EF9F27 #D4537E #5DCAA5 #888780`

### 5.7 拖放：素材 → 层（`_ClipList` + `CueTimeline` 的拖放事件）
- 私有 mime：`CLIP_MIME = "application/x-ercue-clip"`，内容 = clip_id 的 utf-8
- `_ClipList.startDrag`（`62-81`）**自己造 QDrag**（不靠内部模型）；`mimeData` 也重写（`84-89`）双保险
- 时间轴 `dragEnterEvent/dragMoveEvent/dropEvent`（`149-170`）；`_clip_from_event`（`118-146`）**两级兜底**取 clip_id（mime → 拖拽源控件 currentItem 的 UserRole）

### 5.8 视口自适应（`_sync_view:2008-2047`）
- `_bl` = `engine._cue_beat_len(...)` 或 0.5；同时 `tl.beat_len = _bl`（**漏这行会导致非 120BPM 时秒数全错**）
- 总长 `total`（秒）：**有音频用歌曲真实时长 `identity.duration_sec`**（≤1s 时用 `probe_duration` 实测）；没有才用"最后一个 cue 终点 + 5 秒"（下限 10 秒）。
  - ⚠ **不能读 `self.audio.duration()`**（那是预览播放缓冲的时长，没按过 ▶ 时为 0）——审查 S1 真根因（5 分钟的歌被撑成 10~20 分钟）
- `tl.set_view(0, max(8.0,total)/bl)`；`sld.setRange(0, int(total))`

### 5.9 位置统一入口（`_set_pos:2405-2432`）
> 滑杆 / 播放头 / 自动播放 / 模拟源 **四处同步的唯一入口**。
- ⚠ **单位是秒**（用户要求"坐标轴就是时间"）；要拍的地方再 `/beat_len`
- 写 `self._pos`、更新滑杆（非滑杆来源时 blockSignals）、更新 `lbl_pos`、`tl.set_playhead(sec/bl)`、`prev.set_pos(sec/bl)`

## 6. ★★ 坑位清单（最重要）

> 每条：**现象 → 根因 → 修法 → 证据（文件:行号 / 补丁名）**。
> 这些坑分两类：① 通用陷阱（重写时必须避免）；② 宿主集成副作用（新项目通常没有）。

### 6.1 素材拖不进层 / 双击加 cue 失败（★★★ 用户实际报障）

**现象**：用户报「素材拖不进层」+「无法添加素材到时间轴」。三条入口（拖放/双击/＋）都失效。

**根因（两个独立 bug 叠加）**：
1. **`_clip_from_event` 是 `@staticmethod` 却在里面用了 `self`** → `NameError` 被外层 `except` 吞掉 → mime 分支等于不存在，只剩 `e.source()` 兜底；source 一旦为 None 整条拖放就废。（`cue_editor.py:118-146` 注释逐字记录）
2. **`_append_cue` 里写了未定义的 `at_sec`** → `NameError` → append 前炸掉，cue 根本没进层。（`cue_editor.py:2124-2127` 注释原文："用户 2026-09-29 报…就是它"）
3. **素材列表 UserRole 存的是文件路径而不是 clip_id** → 把路径当 clip_id，加 cue 必然失败。（`cue_editor.py:1045-1048` 注释）

**修法**：
1. 去掉 `self`，改为从 `e.mimeData()` 读 + 加 `e.source().currentItem()` 兜底；`_ClipList.startDrag` 自己造 QDrag（`_patch_cue_dragclip.py`）
2. `it.at_sec = float(at) * beat_len`（`_patch_cue_bugs1.py` 之后的修正）
3. UserRole = clip_id，UserRole+1 = 路径（`_patch_cue_addclip.py`）

**新项目教训**：`@staticmethod` 里绝不能用 `self`；异常别用裸 `except` 静默吞（这个 bug 被吞了不知多久）。

### 6.2 素材拖拽 mime 不生效（Qt 模型/视图细节）

**现象**：重写 `QListWidget.mimeData()` 后，时间轴 `hasFormat(CLIP_MIME)` 仍为假。

**根因**：PySide6 里真正参与拖拽的是列表**内部模型**的 mimeData，视图重写的 `mimeData()` 不保证被调用。

**修法**：在**视图自己的 `startDrag()`** 里造 QDrag（一定被调用）；同时保留 `mimeData()` 做双保险。（`cue_editor.py:62-89`，`_patch_cue_dragclip.py`）

### 6.3 ★★ 码表图层每帧重建解码器（性能事故，CPU 12 核 / 磁盘 500MB/s）

**现象**：CPU 1130~1580%、磁盘持续读 500~750MB/s，画面还卡。

**根因（两层）**：
1. `_get_player()` 的通用 LRU 用 `lay.clips[lay.cur].path` 保护"当前正在播的那个"。但**码表图层是容器，`clips` 为空** → `cur_path==""` → 一个解码器都保护不了 → 每帧新建+淘汰 → 反复开容器（部分容器要扫全文件）。
2. 修好 #1 后，`_cue_set_active` 只遍历 `lay.cache`，**没遍历码表自己的 `lay._cue_players`** → 码表解码器一旦激活就再没人关掉 → 每碰一个素材就多一个后台解码器一直读盘/一直解码，越用越多互相抢 IO。

**修法**（`_patch_cueplayer_cache.py`，`engine.py:1643-1668`）：
- 码表图层用**独立的 `lay._cue_players`** 缓存，容量按素材数给足（`cap = max(32, len(cue_media)+16)`），淘汰时**只淘汰当前没活跃的**
- `_cue_set_active`（`engine.py:2420-2441`）**两个缓存都遍历**（`lay.cache` 和 `lay._cue_players`），按 `pth in paths` 置活跃
- 卸载码表时关掉这份缓存（`clear_cue_sheet:2262-2269`）

**新项目教训**：编辑器预览也要自己的解帧缓存（见 6.4），**绝不能每帧新建播放器**。

### 6.4 ★ 预览取帧每帧重试失败素材 = 硬盘狂读

**现象**：失败素材每帧重试一次 → 硬盘狂读。

**根因**：`make_player()` 会开容器、起解码线程、部分容器还要扫全文件；失败素材每帧重试一次就是灾难。

**修法**（`cue_preview.py:CueFrameSource.frame:231-264`）：
- 成功就**复用**播放器；失败记 `_fail[path] = now + RETRY_SEC(2.0)`，**退避 2 秒**内直接返回 None（画面留空也比烧硬盘好）
- 首帧还没解出来是正常的"等一帧"，**不算失败**但要限速（别每帧都问）

### 6.5 ★★ 预览性能：定时器 / 重合成 / 帧率

**现象**：静止时也在烧 CPU（实测能烧掉十几核）。

**根因**：`_tick` 每 100ms 无脑重算所有片段（还要取帧）。

**修法**（`cue_preview.py:_tick:327-334`）：
- **只有** `self._dirty`（位置变了）或 `self.playing`（正在播）才重新合成
- 帧率从 25fps 降到 **10fps**（`FPS=10`，注释："25fps 纯属浪费：看编排 10fps 足够，CPU 直接降一半多"）
- `set_active(False)` 时 **`src.close()` 关掉所有解码器**（它们会一直解码/占着文件句柄）

**实测教训原文**（`cue_preview.py:233-237`）："用户现场 CPU 12 核 / 磁盘 500MB/s：绝不能每帧重建播放器"。

### 6.6 ★ 音频播放的两个坑（音乐变慢 / 画面空转）

**现象 A「音乐被拉长了」**：BLOCK 每次 1024 帧（仅 21ms），`p.play()` 每 21ms 调一次，单次开销一旦超过 21ms 就供不上 → 声卡欠载 → 音乐变慢/断续。
→ **修法**：`BLOCK = 12000`（0.25 秒一块，4 次/秒）（`cue_preview.py:31-35`，`_patch_cue_bugs1.py`）

**现象 B「音乐关了画面还在走」+ 音画不同步**：
- 旧写法「解码线程 → 有界队列 → 声卡」，队列满丢块、空插静音 → ① 丢块/欠载让音乐比挂钟慢（听感被拉长、越走越偏）；② 位置用挂钟推算 → 音乐停了画面还在按挂钟走。
- **修法**（`cue_preview.py:CueAudio:41-196`）：**先把整首解码到内存**（48k 立体声 float32，6 分钟约 138MB），播放循环只做「交给声卡 → `_i` 前进」；**位置 = 实际交给声卡的帧号 / 采样率**（停了就不动）；播放前预载 0.5s（`PREROLL_SEC`）；欠载时短等而不是丢块。
- ⚠ soundcard 有 COM/线程约束 → 播放放**专用线程**（项目铁律：不在 GUI 线程碰它）；`stop()` join 超时 0.8s **绝不卡界面**。

### 6.7 ★ 预览画面：素材被拉伸变形 + 淡入被"平方"

**现象**：「一段视频放上去自己铺满了」（非 16:9 素材被拉变形）。

**根因**：旧 `_rect` 写 `w = W*scale / h = H*scale` → 直接铺满画布。

**修法**（`cue_preview.py:_rect:378-396`）：**先按素材原始比例 contain 适配画布**（`k = min(W/fw, H/fh)`），再乘用户 scale。

**另一个**：淡入变"硬"（审查 M9）—— 运行时的 `alpha` 已含淡入量（`alpha = trans_p = a_in`），预览**又乘了一次 `trans_p`** → 淡入变平方曲线。
→ **修法**：`p.setOpacity(opacity × alpha)` **只乘一次**（`cue_preview.py:361-363`）。

### 6.8 ★ 时间轴标尺单位从「拍」改「秒」（用户 2026-09-29 要求）

**现象**：用户："导入的视频多长，编排就该按真实时间对" → 坐标轴改秒。

**连锁坑**：
1. 改了坐标轴但**漏了 `tl.beat_len = _bl`** → 标尺仍按默认 0.5s/拍算，**非 120BPM 就是错的**（`_patch_fp_primary_sec.py` 注释："漏了这行 ⇒ 秒数全错"）
2. 属性面板单位混乱（拍 vs 秒）→ 统一：**面板显示秒，存储仍是拍**（`_patch_fp_primary_sec.py`：读时 ×bl、写时 /bl，同时写 `at_sec`）
3. 吸附档位的数值把"小节"错写成 0.5 拍（审查 M1）→ 改 4.0
4. `_fix_two_tests.py`：标尺测试的阈值/档位断言跟着改（数字 30→34px、"lab_step≥128"→"step≥60s"）—— **说明纯自测断言也会随单位变更失效**

### 6.9 ★ 时间轴长度算错（5 分钟的歌被撑成 10~20 分钟）

**根因**：`_sync_view` 读了 `self.audio.duration()` —— 那是**预览播放缓冲**的时长（没按过 ▶ 时为 0；按过之后一直留着上一首的时长）。审查 S1 真根因。

**修法**：改用 `identity.duration_sec`（≤1s 时用 `probe_duration` 实测音频文件）；没有音频才用"最后一个 cue 终点 + 5 秒"。（`cue_editor.py:2013-2039`）

### 6.10 ★ QComboBox 每 500ms 重填 / 信号风暴

**现象**：`_refresh` 每 500ms 重建 `cb_layer` 与 `cb_layer_view` 的列表 → 触发 `currentIndexChanged` 会引起连锁反应。

**修法**：重填前 `blockSignals(True)`、填完恢复，并 `findData(cur)` 把选中项还原（`cue_editor.py:1790-1812`）。
**同类**：`cb_sheet` 的 `_del_sheet` 删项也 blockSignals（`1146-1151`）；`_fill_track_list:1337/1349`、`_fill_clip_combo:2000/2006`、`_sync_props:2224/2229` 同理。

**新项目教训**：凡是"定时重填的下拉框"必须 blockSignals + 还原选中项，否则就是信号风暴。

### 6.11 ★ 重入：回填数据时挡住写回（`_tloading` / `_loading`）

**现象**：面板回填 → 触发 `valueChanged` → 又写回数据 → 又刷新 → 自激。

**修法**：`_tloading`（曲目回填，`1379/1395`）、`_loading`（属性回填，`2234/2259`）标志位，回填期间 `_apply` 直接 return。（`_sync_track_props:1377` / `_sync_props:2208` / `_apply_track:1397` / `_apply:2261`）

### 6.12 「新建第二张码表后切回第一张，两张都空了」

**复现脚本**：`tools/_repro_two_sheets.py`（注释："复现用户 #4"）。脚本流程：新建 A → 加素材+cue → 新建 B → 改 B → 切回 A，检查 A/B 的素材与 cue 是否还在。

**性质**：跨码表状态串味（新建/切换时共享了引用或 `_pick_sheet` 处理不当）。最终版 `_sheets` 用**名字为 key 的 dict、每张独立存 `{sheet, media, path}`**（`cue_editor.py:628`、`_register_sheet:1538-1557`、`_pick_sheet:1973-1997`），每张码表的 `sheet`/`media` 各存一份、切换时整体替换 `self._cur`/`self._media`。

**新项目教训**：多文档（multi-document）必须**每个文档持有自己完整的模型对象**，不要用全局单例 + 局部字段拼装。

### 6.13 编辑器内嵌时后台空跑（主线程不做无用功）

**现象**：嵌进主窗口后切走，500ms 刷新定时器还在跑；预览还在刷新。

**修法**（`set_active:650-669`）：
- 切走时若正在播放先停播
- `embedded` 时按 on 开关 500ms 定时器
- `prev.set_active(on)` 控制预览画布（离开页面关解码器）
- `_build` 时定时器**只在 `not embedded` 才自启**（`646-647`）

### 6.14 淡入淡出的"回滞"与"大跳变"（运行时解释器）

> 来自 `cuesheet_runtime.py:10-15` 的四条规则 + `selftest` 的踩坑记录：
1. **位置一律以位置源为权威**，本模块只消费拍位，不自己推断
2. **回滞 0.15 拍**（`HYSTERESIS_BEATS`）：边界抖动不许来回触发
3. **大跳变直接重算、不做过渡**（`BIG_JUMP_BEATS = 8.0`，2 小节）：位置倒退或前跳 >8 拍（DJ 打 loop / 跳段）立刻跟上，慢慢淡入更难看
4. **缺素材只跳过该 item**，绝不让整条链断掉
- ⚠ **测试陷阱**（`cuesheet_runtime.py:227-235` 注释原文）："必须**模拟逐帧单调推进** —— 真实引擎每帧都会调用 update。**瞬移测试会（正确地）被判成'跳转'，测不到过渡（我第一版就这么写错了）**。"

### 6.15 预览 alpha 与 z 顺序（运行时→合成的契约）
- 返回的 states **必须按 z 升序**（引擎按序绘制 ⇒ z 大的在上）；自检有断言（`cuesheet_runtime.py:302-304`）
- `play_sec = src_in_sec + (dt_beats × beat_len) / speed`（变速折算，`174`）
- `end_beats` 到期后该层失活（`306-311` 自检）

### 6.16 位置源工程铁律（若保留模拟源需遵守）
来自 `position_source.py:6-17`（"违反会在现场出事"）：
1. **探测（`probe`）与建立（`start`）必须是两个函数**（NDI 的坑就是这么踩的）
2. **一切探测/监听在后台线程**，主线程绝不碰
3. **失败绝不影响演出**（接不到 → 退回自动切换，不黑屏/不弹模态/不阻塞）
4. **只读，绝不对设备写**；端口占用要优雅报 `blocked`
- **节流铁律**：碟机 beat 消息 10~100Hz，回调里**只更新一份最新快照**，引擎每帧读；**绝不把高频回调直接接进 Qt 信号**
- ⚠ `VdjSource.probe` 必须绑 `0.0.0.0`（与运行时一致）；绑 `127.0.0.1` 会**漏报端口占用**（`position_source.py:329-331`，踩过一次）
- ⚠ 沙箱里 UDP 本机回环收不到 → 自检改为**直接喂 OSC 消息**（`position_source.py:604-626`）

### 6.17 音画锚点：时间轴第 0 拍 = 音频第几秒

**坑**：若锚点按 0 算，音乐真正的小节/乐句头**不会落在时间轴的 ◆ 线上**，整条编排跟音乐整体错开，看着像"没对上"。

**修法**：`_audio_anchor_sec()` 用离线节拍网格的 `anchor × beat_len`（`cue_editor.py:1758-1772`）。

### 6.18 循环播放只回画面不回音频（审查 M2）

**现象**：勾「循环」后到末尾只把画面拉回 0，下一帧又判成"播完了"再停一次。

**修法**：循环时必须**把音频也重起来**（`cue_editor.py:1693-1703`）。

### 6.19 播放头三处同步（审查 M3）
编辑器自己在播时，播放头以 `self._pos` 为准，**不要**被引擎状态覆盖（`_refresh:1850-1853`）。

### 6.20 改 BPM/时长后标尺不刷新（审查 M4）
`_apply_track` 改完必须调 `_sync_view()` 重算标尺与时间轴长度（`1413`）。

### 6.21 patch 脚本本身的坑（工具链教训）
- ⚠ **bash heredoc 会吃掉行尾 `\n` 的一个字符**（实测 `else:\n` 变 `else:/n`，导致替换静默匹配 0 处）。`_patch_engine_cue.py:5` 与 `_patch_cue_ui.py:4` 都记录"这个坑连续踩了两次"。→ **补丁必须写成文件用 python 执行**。
- 所有 patch 断言"恰好 N 处命中"，任何一处对不上就整体不写入（**原子**），避免半应用。

### 6.22 `_get_player` 里 `MediaItem` 替身的坑（引擎侧，新项目不涉及但值得记）
- 取帧必须用**真实 `MediaItem`**（播放器工厂需要 `kind`/`_thumb_path()`/`_has_alpha`）；自造替身会让工厂抛异常 → **静默黑屏**（`engine._cue_item:2492-2496`）
- `VideoPlayer._active` **默认 False**（省 CPU），没人显式 `set_active(True)` 的话 `current()` 永远 None → 「码表图层一片黑」且**不报任何错**（`engine._cue_set_active:2422-2427`）——"这个坑很隐蔽"

### 6.23 认歌匹配失败不应提交 sid（审查 严重-4a）
见 §4.3：`_cuesheet_autoswitch` 里 `tr is None` 时**不要**更新 `_cue_sid`，否则首次没匹配上后永不重试。

## 9. 重写建议（供 team-lead / software-engineer 参考，非考古结论）

1. **先移植 `cuesheet.py` + `cuesheet_runtime.py`（纯逻辑、无 Qt）**，直接跑它们的 `selftest()` 验证环境（`python -m cuesheet; python -m cuesheet_runtime`）。这两个文件几乎可以原样复制。
2. **`CueTimeline` 是重写的最难点**（自绘 + 拖拽 + 平移 + 缩放 + 吸附 + 跨层）。建议**原样搬**再改，不要凭描述重画——§6.1/6.2/6.8 的坑都在细节里。
3. **信号自激**（§6.10/6.11）是 Qt 面板最容易翻车处：所有"回填控件"必须走 `_loading` 标志 + `blockSignals`。
4. **预览取帧**照抄 `CueFrameSource`（退避 + 复用 + 只 dirty 时重合成 + 离开页面关解码器）。
5. **单位纪律**：明确"UI=秒、存储=拍"，写一个统一的换算入口（旧实现靠 `_bl` 满天飞，是 §6.8 那堆坑的根）。建议新项目**统一内部用秒**、拍只作为显示/吸附的派生物，或反之——**只能选一个，别混**。
6. **属性面板补上"入/出点"控件**（旧实现的数据模型早就有 `src_in_sec/src_out_sec`，只是从没做 UI 也没做 seek）——**但这依赖解码器 seek 能力**，新项目若用 PyAV 可直接 `seek()`，会**比旧实现容易得多**。
7. **放弃 `at_sec` 冗余字段或严格维护它**。旧实现里 `at_sec` 多次成为 bug 源（NameError、单位混用），导入时也不信任它。
8. **导出前检查**（缺素材/超长/未吸附清单）旧实现没有，是新项目该补的短板。

**统计**：功能点 **约 95 项**（顶栏 8 + 状态行 1 组 + 4 标签页约 60 + 预览/传输 8 + 时间轴交互 12 + 播放逻辑 5）；坑位 **约 28 条**（含子项）。

**最关键的 3 个坑**：
1. **§6.3 码表图层每帧重建解码器**（容器层 LRU 保护失效）—— 直接导致现场 CPU 12 核 / 磁盘 500MB/s 的性能事故，是"用户判断码表有问题"的最可能真凶之一。
2. **§6.1 素材拖/加 cue 全废**（staticmethod 里用 `self` 的 `NameError` + `at_sec` 未定义 + UserRole 存了路径）—— 三个独立 bug 叠加，且被裸 `except` 静默吞掉，用户直接"加不进去"。
3. **§6.8+§6.11+§6.10 单位与信号纪律**（坐标轴改秒的连锁 + 面板自激 + 下拉框信号风暴）—— 这类"看起来是功能 bug、其实是状态同步纪律"的问题最易在重写时复发。
