# EasyRealityCue 架构方案

> 项目：**Easy Reality Cue** —— DJ 码表（Cue Sheet）编排编辑器
> 定位：**纯编排（Authoring）工具**，单窗口，不做实时演出播放 / NDI / Spout / GPU 解码 / DXV。
> 路径：`P:\EasyRealityCue`
> 依据：`docs/规格书_旧实现考古.md`（旧实现 4485 行的功能与坑位考古）+ `docs/技术选型.md`

---

## 0. 一句话

DJ 用这个软件给一首歌排出「第几秒/第几拍，哪一层显示哪段画面、怎么摆、怎么混、怎么进怎么出」，
导出成一个 `.ercue` 文件交给演出端。

**与旧实现的根本区别**：旧的是长在 AutoVJ 里的第 3 个界面，与演出引擎强耦合；
新的是一台**独立、干净、只做编排**的机器。

## 1. 设计原则（重写的四条底线）

| # | 原则 | 说明 |
|---|---|---|

## 3. 关键设计决策

### 3.1 单窗口，无"模式"

旧实现有 `embedded=True/False` 双模式（嵌主程序 / 独立窗口），带来一堆"切走要停定时器"的代码。
新项目**只有独立窗口**一种形态。所有定时器常驻（因为窗口存在即代表在做编排）。

### 3.2 ★★ 单位纪律：内部唯一坐标 = **秒**

**旧实现最惨的一类坑（§6.8）** 源于两个坐标系并存：时间轴横轴是秒、数据存的是拍、
面板显示秒、存储是拍、吸附用拍、标尺用秒……`_bl` 满天飞，漏一处就全错。

**新项目的铁律**：
```
对外（UI / 交互 / 显示 / 时间轴横轴 / 音频 / 素材时长）  →  一律【秒】
对内（编排数据模型 CueItem 的坐标）                      →  一律【秒】
文件格式 .ercue                                          →  仍是 at_beats（主）+ at_sec（冗余）
                                                            ↕ 只在 ercue_io 的读写边界换算一次
拍（beats）                                                →  只是"吸附网格"与"标尺刻度"的派生物
```
- `units.py` 提供唯一换算：`sec_to_beats(sec, bpm)` / `beats_to_sec(beats, bpm)` / `snap_grid(mode, bpm)`。
- **除 `units.py` 与 `ercue_io.py` 外，任何地方出现 `/ beat_len` 或 `* beat_len` 都视为违规。**
- `bpm` 来源：`track.identity.bpm`；为 0 或缺失时**退化为"整拍=1 秒"**并禁用拍吸附档位（UI 上置灰），绝不猜。

> 这条直接消灭旧实现的 4 类 bug：漏 `tl.beat_len`、面板拍秒混用、吸附把小节写成 0.5、标尺秒数错。

### 3.3 多文档模型：每个码表持有完整模型对象

旧坑 §6.12：「新建第二张码表后切回第一张，两张都空了」。
旧实现用 `_sheets`（名字→dict）拼装 `self._cur` / `self._media`，切换时共享引用出问题。

**新项目**：
```python
class SheetSession:          # 一张码表 = 一个 session，自持全部状态
    sheet: CueSheet          # 数据模型（含 media、tracks）
    dir: Path                # 素材搜索根目录
    dirty: bool
    undo: UndoStack          # 撤销栈（每张码表独立）
```
主窗口只持 `sessions: dict[str, SheetSession]` 与 `current_key`。
**切换 = `current_key` 改一下**，不存在任何"字段拼装"。

### 3.4 命名与 id 生成

| 对象 | 生成规则 | 唯一性范围 |
|---|---|---|
| `clip_id` | `c1, c2, …`（递增，不回收） | 整张码表 |
| `lyr_id` | `L1, L2, …` | 整张码表 |
| `item_id` | `i1, i2, …` | **层内**（旧实现换层撞名会改成 `i{k}_{len}`，新项目直接用全局递增，避免撞名逻辑） |
| `track_key` | `identity.meta_id[:12]` | 整张码表 |

### 3.5 撤销/重做（旧实现没有，新项目补上）

编排工具没有撤销无法用。基于**命令模式 + 模型快照**：
- 每个会改数据的操作产出一个 `Command`（`do` / `undo`）。
- 简单起见：对 `CueSheet` 的 **`to_state_dict()`** 做 JSON 快照（编排数据量小，一张码表几十 KB），
  压栈 `[快照]`，上限 50 步。实现简单、绝不会漏。
- ⚠ **注意坐标**：`to_state_dict()` 产出的是**内部状态快照（秒坐标）**，
  与 `ercue_io.sheet_to_file_dict()` 的**文件形态（拍坐标）**是两回事 —— 快照**绝不用**文件形态，
  否则撤销/重做会在每次换算里累积浮点误差。
- ⚠ 序列化方法名字即契约：一切 `*_state_dict()` = 秒；一切 `*_file_dict()` = 拍。
  看到裸的 `to_dict()` 视为命名违规。
- 快捷键 `Ctrl+Z` / `Ctrl+Shift+Z`。

## 4. ★★ 重写纪律（从旧实现 28 个坑提炼的硬约束）

> 每条都对应旧实现真实烧过的代价。**代码评审逐条对照；能写成断言/测试的必须写。**

### A. 性能与资源

| # | 纪律 | 旧代价 |
|---|---|---|
| A1 | **绝不每帧新建解码器**。取帧走 `CueFrameSource` 缓存，同一路径复用播放器实例。 | CPU 12 核 / 磁盘 500~750MB/s（§6.3） |
| A2 | **失败素材必须退避**：记录 `_fail[path] = now + 2.0`，退避期内直接返回 None。**首帧未出 ≠ 失败**，但也要限速。 | 硬盘狂读（§6.4） |
| A3 | **预览只在 `dirty`（位置变）或 `playing` 时重合成**，帧率 **10fps** 封顶，静止时 CPU 必须≈0。 | 静止烧十几核（§6.5） |
| A4 | **离开/关闭时必须释放解码器**（`close()`），否则文件句柄与后台解码线程常驻。 | 同上 |
| A5 | **音频一次解码进内存**，播放循环只做"交给声卡 → 索引前进"；**位置 = 已交声卡帧号 / 采样率**。块大小 **≥ 0.25s**。 | 音乐被拉长、画面空转（§6.6） |
| A6 | soundcard 的调用**只在专用线程**，`stop()` 带超时（≤0.8s）**绝不卡 UI**。 | 同上 |

### B. Qt 状态同步（最易复发）

| # | 纪律 | 旧代价 |
|---|---|---|
| B1 | **任何"定时重填的下拉框/列表"必须 `blockSignals(True)` → 填 → 恢复 → `findData()` 还原选中项。** | 信号风暴（§6.10） |
| B2 | **任何"数据→控件回填"必须走 `_loading` 守卫**，守卫置位**必须在动控件之前**，且**必须有 ≥2 处独立复位**。 | 面板自激；守卫写在赋值后=没写（§6.11） |
| B3 | **禁止裸 `except` 静默吞异常**。至少要 `log.exception`。旧实现的一个 bug 被吞掉不知多久。 | §6.1 |
| B4 | `@staticmethod` / `@classmethod` 里**绝不能用 `self`**。 | §6.1 |
| B5 | 拖拽：**在视图的 `startDrag()` 里自己造 `QDrag`**（PySide6 里视图重写的 `mimeData()` 不保证被调用）；同时保留 `mimeData()` 双保险。 | §6.2 |
| B6 | 列表项的 `UserRole` 存 **id**，路径另存 `UserRole+1`。**绝不能把路径当 id**。 | §6.1 |

### C. 坐标与单位

| # | 纪律 | 旧代价 |
|---|---|---|
| C1 | 见 §3.2：内部唯一坐标 = 秒；`beat_len` 只在 `units.py` 出现。 | §6.8 四连锁坑 |

### D. 渲染契约

| # | 纪律 | 旧代价 |
|---|---|---|
| D1 | **素材按原始比例 contain 适配画布**，再乘用户 scale。绝不直接 `W*scale` 铺满。 | 素材被拉变形（§6.7） |
| D2 | **alpha 只乘一次**：运行时的 `alpha` 已含淡入量，合成时 `opacity × alpha`，不得再乘 `trans_p`。 | 淡入变平方曲线（§6.7） |
| D3 | **层按 z 升序返回/绘制**（z 大的在上）。此契约写断言。 | §6.15 |
| D4 | `play_sec = src_in_sec + 已播时长 × **speed**`（变速折算）。⚠ **必须是"乘"，不是"除"** —— 见下方勘误。 | §6.15 |

> ### ★★ D4 勘误：旧实现的 `/ speed` 是 bug，新项目用 `× speed`
>
> `规格书_旧实现考古.md` §6.15 记录的旧公式是 `play_sec = src_in_sec + (Δt × beat_len) / speed`
> （`cuesheet_runtime.py:174`）。**这是错的**，与它自己的播放器语义相反。
>
> **实证链（2026-10-01 逐处查证）**：
> 1. `media_manager.py:817`（全部四个播放器同此式）：`wait = float(interval / self.speed - (perf_counter() - t0))`
>    ⇒ speed 越大，帧间隔越短、帧出得越快 ⇒ **speed 是倍速（speed=2 = 快 2 倍）**。
> 2. `engine.py:359` 注释原文：`self.speed = 1.0  # 图层播放速度倍率`。
> 3. `audio_engine.py:116` 原文：`与引擎里 speed（输出端 VJ 素材倍速）完全是两回事`。
> 4. `ui_main.py:4496` 菜单名：`播放速度`。
>
> ⇒ **演出端 `speed=2` 是快放**；而旧运行时解释器算出来的 `play_sec` 是**慢放**。
> 两者矛盾 ⇒ 旧编辑器**预览的变速方向与现场演出相反**，用户照预览调好的编排，演出时会反。
>
> **新项目裁定（team-lead）**：采用 `× speed`，与演出端一致。
> `timeline.py` 里此取舍已写成注释，**任何"改回除法"的改动都必须先推翻上面四条证据**。

## 5. 技术栈（依据 `docs/技术选型.md`，均为本机实测）

| 库 | 版本 | 用途 | 许可 |
|---|---|---|---|

| **PySide6-Essentials** | 6.11.2 | GUI / 自绘时间轴 / 预览合成 | LGPL-3.0（动态链接可闭源） |
| **PyAV (av)** | 18.1.0 | 视频·音频解码 / **随机 seek** / alpha / 取帧 | BSD-3（⚠ wheel 内含 GPL 的 libx264/x265，见 R1） |
| numpy | 2.5.3 | 混合运算 / 频谱 / 节拍网格 | BSD-3 |
| onnxruntime | 1.30.0 | 跑 Beat This! 小节识别模型 | MIT |
| Beat This! `small0_fixed.onnx` | 9.9 MB | 小节头 / BPM 离线识别 | **MIT，可商用** |

**不装**：`opencv-python`（PyAV 全覆盖且更快，省 97 MB）、`PySide6.QtMultimedia`（**本 wheel 无多媒体后端**，实测支持格式数=0）、`librosa/aubio/madmom/scipy/numba`（节拍识别是纯 numpy + onnx）。

### 5.1 预览合成器：纯 Qt 光栅路线（不用 OpenGL）

**实测结论**：`QPainter.CompositionMode` 覆盖 7 种混合里的 **6 种原生**，只有 `subtract` 无原生 → 用 numpy 原地饱和减补上。

| 需求 | Qt 取值 |
|---|---|
| normal | `CompositionMode_SourceOver` |
| add | `CompositionMode_Plus` |
| screen | `CompositionMode_Screen` |
| multiply | `CompositionMode_Multiply` |
| lighten | `CompositionMode_Lighten` |
| darken | `CompositionMode_Darken` |
| **subtract** | ❌ 无 → numpy **饱和减** `max(0, dst−src)`（等价式 `dst − min(dst, src)`；⚠ 必须**逐层渲染后立即施加**，多块 scratch 会串） |

> ⚠ **勘误**：`技术选型.md` §B7 里的 `np.maximum(dst, 255−src)` **不是相减**，那是当次为测速度临时写的
> 近似式（原文自己也标了"仅测速度"）。**正确公式是 `max(0, dst−src)`** ——
> 与旧引擎 `engine.py:2968 _apply_subtract` 的 docstring 原文「画布 RGB 减去图层 RGB（饱和到 0，alpha 不动）」一致。
> 例：dst=40、src=200 ⇒ 正确结果 `0`；错误公式给 `55`。

**性能实测（3 层叠图）**：1080p **6~13 ms/帧（77~155 fps）**、540p **2.7 ms/帧（365 fps）**。
需求只要 8~15 fps ⇒ **余量 5~10 倍，没有理由上 OpenGL**（后者要背驱动/上下文/线程/打包一连串风险）。

合成纪律：一律先合成到**离屏 `QImage(Format_ARGB32)`** 再整幅画到控件；`crop` 用
`drawImage(tgt, img, srcRect)` 源矩形重载（**不 copy**）；scratch 缓冲按图层缓存复用、**绝不在每帧分配**。

### 5.2 解码与 seek

- **`av.open(path, metadata_errors="replace")`** —— 素材库里大量 GBK 元数据的 `.mov` 不加这个会抛 `UnicodeDecodeError`。
- **统一用 `seek(pts, stream=st, backward=True)`**（实测 11~36 ms）。⚠ `any_frame=True` 在 mp4 上**反而慢到 65~819 ms**，禁用。
- 取帧：视频 `frame.to_ndarray(format="bgra")`；**音频帧不能带 `format=`**（抛 `TypeError`）。
- **alpha 判定不能只看 `pix_fmt`**：DXV 一律输出 `rgba`，但实测 40 个 DXV 里真带 alpha 的只有 2 个 ⇒ 必须**实解几帧看 alpha 是否 <255**。
- ⚠ **seek 落在关键帧**（非精确帧）：入/出点要精确时，seek 到目标前一个关键帧再顺序解到目标；或允许"关键帧级"入点并在 UI 标明（见 R6）。

### 5.3 节拍 / 小节识别（整套可搬，零额外依赖）

`beatgrid.py`（1003 行，纯 numpy）+ `phrase_bt.py`（459 行，numpy + onnxruntime 惰性导入）
+ 模型 `small0_fixed.onnx`（9.9 MB）。实测 180s 窗口 **5.05 s/首**，BPM 127.99 / anchor 1.0235 / conf 0.95。
⚠ **必须用 `small0_fixed.onnx`**（网上流传的 `small0.onnx` 是坏的，只出 71 个 beat）。
参考项目 `tools/_beat_this_models/` 那 179 MB 是开发中间产物，**发行只需 9.9 MB 那一份**。
`beatgrid.py` 内建 VirtualDJ `database.xml` 读取，可让编辑器"导入已有 BPM/相位"（只读 XML，成本近零）。

### 5.4 打包

PyInstaller `--windowed --onedir`（**不用 onefile**）。必须 `--collect-all av / onnxruntime / soundfile`；
模型 `--add-data` 并用 `sys._MEIPASS` 解析。⚠ **Qt DLL 本体 `--exclude-module` 拦不住**
（是插件沿 PE 导入表拉进来的），必须在**写 zip 时按文件名跳过**。
实测未裁剪 362 MB → 去掉 cv2 + 跳过未用 Qt DLL 后目标 **约 200 MB 解包 / 120~150 MB zip**。

## 6. 功能范围（v1）

### 做
1. 码表管理：新建 / 导入 / 导出 / 打开最近 / 另存（**多文档 + 撤销**）
2. 素材：添加（视频/图片）、探测、缩略图、缺失标红、指定素材目录重挂
3. 曲目：添加 / 导入音频读标签 / 编辑曲名·艺术家·时长·BPM
4. 时间轴：多层 + 音频轨 + 拍/小节/乐句标尺；拖拽 / 拉边 / 跨层 / 吸附 / 缩放平移
5. 片段属性：素材、**入点/出点**、变速、裁切、位置大小、混合、过渡、时长、备注
6. 预览：随播放头合成（10fps）、音频走带、循环
7. 导出前检查：缺素材 / 超长 / 未吸附 清单
8. 语言：中文（`T()` 机制保留，词表可后补英文）

### 不做（明确）
- ❌ 演出播放、NDI/Spout、GPU 解码、DXV、图层小眼睛、Solo
- ❌ 位置源（VDJ/碟机/中继/小助手）——**连模拟源都不需要**：走带由音频/挂钟驱动，滑杆直接设位置
- ❌ 指纹认歌 / 自动切曲目（编辑器里"认歌"就是用户选歌）
- ❌ 内嵌素材进包（`embed=True` 保留在 IO 层，UI 上只放一个开关，默认关）
