# 时间码 / 码表（Cue Sheet）功能 —— 设计文档

> **v0.2 · 2026-09-27**（v0.1 → v0.2：加入 PR 式时间轴、VDJ 接入定型、版本号体系、三拓扑、素材丢失 UI）
> 状态：**设计评审中（未开工）**
> 本文是内部工程设计笔记，**不进 GitHub 仓库**（`.gitignore` 的 `_*.md` 已覆盖）。

---

## 0. 一句话

DJ 用我们的**独立编辑器**（PR 式时间轴）给某几首歌排出"第几拍放哪一层哪一段画面、放在什么位置、怎么混合"，
导出成一个 `.ercue` 文件；VJ 端导入后**新建一个「码表图层」**并绑定它，演出时**跟着 DJ 设备的实时状态**自动触发。

---

## 1. 目标与非目标

### 目标
1. **码表图层**（图层类型，可多个，每个绑定一张码表）。
2. **位置源抽象层**：从 DJ 设备 / 软件拿实时状态（曲目 / 位置 / BPM / 调性）。
3. **码表编排界面**（第 3 个主界面，PR 式时间轴）。
4. **导入 / 导出** `.ercue` 包（含曲目信息、编排、素材清单、版本号），带向下兼容提示与**素材丢失提示**。
5. **独立码表编辑器**（Windows 先行，macOS 后置）。
6. **三种拓扑**都支持：同机 / 局域网 / 互联网。
7. 顺带修：**NDI 输出补音频 + 开关**；界面写明 Spout 不含音频。

### 非目标（明确不做）
- ❌ **不做灯光控制（LJ）** —— 我们是 VJ 软件。（将来靠格式版本机制扩展，现在不留占位。）
- ❌ **不做 LTC / SMPTE 硬件时间码输入**（v1）。接口留 `position_kind` 扩展位。
- ❌ **不做"整场一条长轴"** 的码表（见 §3-⑫，改用"逐曲 + 模板批量套用"实现同样效果）。
- ❌ **不做 djay 的接入**（原因见 §5.2）。
- ❌ 不接管 DJ 软件的播放控制（**只读，绝不回写对方设备**）。
- ❌ v1 不支持 macOS 版编辑器。

## 2. 术语

| 术语 | 含义 |
|---|---|
| **码表（Cue Sheet）** | 针对**一首歌**的一份编排（下挂多层、每层若干时间段） |
| **码表包（`.ercue`）** | 可交换的单文件容器（zip），内含编排 JSON + 可选素材 |
| **层（Layer）** | 码表内的合成层（与软件主界面的图层概念一致：上层优先显示） |
| **片段（Item）** | 某一层在时间轴上的一个时间段（含素材、位置、裁切、变速、过渡） |
| **位置源（Position Source）** | 提供"当前放的是哪首、放到哪了"的抽象接口 |
| **适配器（Adapter）** | 位置源的具体实现（vdj / pioneer / denon / serato / relay / sim） |

## 3. 已拍板的核心决策

| # | 决策 | 理由 |
|---|---|---|
| ① | **逐曲码表**，不做整场长轴 | DJ 会改顺序 / 插曲 / 跳首 / loop；整场轴一改全崩 |
| ② | cue 位置**主坐标是"拍"**（`at_beats`），`at_sec` 只作冗余 | 变速不改变拍/相位，只改变秒；与既有节拍网格同坐标系 |
| ③ | 认歌用**三级匹配**（指纹 → 元数据 → 文件名） | 指纹最可靠；VJ 端没文件时必须能靠元数据兜底 |
| ④ | **位置一律以「位置源」为权威** | 碟机知道播到第几秒；音频推断会被**重复段落骗**（见 §6 警告） |
| ⑤ | **VJ 端不需要有那首歌的音频** | 位置由设备给，我们只需要"是哪首歌"来确定用哪张码表 |
| ⑥ | **过渡由用户自选，不写死淡入淡出** | 复用引擎已有的 5 种：`fade / cut / slide / zoom / glitch` |
| ⑦ | 码表图层**绑定图层的小眼睛** | 眼睛打开才检测位置源与触发；关掉完全不跑（省 CPU、防误触发） |
| ⑧ | **绑定码表后图层名自动改成码表名** | 多张码表并存时一眼可辨 |
| ⑨ | 编辑器**主推逐曲 + 模板批量套用** | 等价于"整场"的便利，但没有整场轴的脆性 |
| ⑩ | 认不出 / 无位置源 → **退回现有自动切换**，绝不黑屏 | 现场安全第一 |
| ⑪ | 先做**抽象层 + 模拟位置源**，再挑真机 | 格式和界面定了，接哪家都只是换适配器 |
| ⑫ | 编辑器**先只做 Windows**；macOS 后置 | mac 上 Qt+GL+FFmpeg 打包是坑；DJ 端做码表不需要播 DXV |
| ⑬ | 不预留隐藏的灯光设置 | 留空容易烂尾，将来靠格式版本机制扩展 |
| ⑭ | 界面 = **PR 式时间轴**（下音频轨 + 上多层视频/图片） | 用户明确要求；且引擎已具备多图层 / 位置 / 混合 / 变速能力 |
| ⑮ | **五种版本号分离**（见 §4.4） | 程序版本与文件格式版本绝不能绑死 |
| ⑯ | 素材丢失**必须在 UI 上看得出来** | 时间轴红底白字 + 导出前检查清单 |
| ⑰ | **P1 先做 VirtualDJ** | 用户手上无真机，只有 djay + VDJ + 两个控制器；VDJ 有现成通路（§5.2） |

## 4. 数据模型

### 4.1 码表包 `.ercue`（zip 容器）

```
my_track.ercue (zip)
├── cuesheet.json          编排主数据（必需）
├── media/                 可选：内嵌素材
│   ├── a3f19c.mp4
│   └── ...
└── thumbs/                可选：素材首帧缩略图（编辑器预览用）
```

**为什么用 zip**：单文件便于传（微信 / 网盘 / QQ 群），可内嵌素材；不内嵌时只有几 KB。

### 4.2 `cuesheet.json` 结构（v0.2：从「cue 列表」升级为「每首歌一个小型合成工程」）

```jsonc

  "format_version": 1,
  "generator": {"tool": "EasyReality CueSheet Editor", "version": "1.0.0", "os": "Windows"},
  "created_at": "2026-09-28T21:00:00+08:00",
  "min_app_version": "2026.10.01.00",
  "requires_features": ["layer_multi", "clip_crop", "clip_speed", "trans_glitch"],

  "author": {"name": "DJ XXX"},
  "title": "某场演出码表",
  "notes": "",

  "media": [
    {"clip_id": "a3f19c", "name": "intro.mp4", "sha256": "…", "embedded": true,
     "duration_sec": 12.5, "fps": 30, "has_alpha": false}
  ],

  "tracks": [
    {
      "track_key": "t1",
      "identity": {
        "fp_id": "…",                 // 指纹（强烈建议带）
        "meta_id": "…",               // 曲名+艺术家+时长 归一化哈希
        "title": "Cosmic String", "artist": "Rolling Contact",
        "duration_sec": 372.4, "bpm": 155.03, "key": "8A",
        "file_name": "Rolling Contact - Cosmic String.flac"
      },

      "composition": {

            "opacity": 1.0,
            "items": [
              {
                "item_id": "i1",

                "trans_in": "fade", "trans_in_beats": 2.0,
                "trans_out": "fade", "trans_out_beats": 2.0,
                "snap": "bar",           // off/beat/bar/phrase —— 编辑器吸附档位（记录意图）
                "note": "副歌进来"
              }
            ]
          },
          {
            "lyr_id": "L2", "name": "前景 LOGO", "z": 10,
            "blend": "screen", "opacity": 0.85,
            "items": [ {"item_id": "i2", "clip_id": "b71f0d", "at_beats": 0.0,
                        "end_beats": null, "xform": {"scale": 0.25, "x": -35.0, "y": 35.0},
                        "trans_in": "cut", "trans_out": "cut"} ]

        ]

```

**与主软件字段的对应关系**（复用，不另造轮子）：

| 编排字段 | 引擎已有的 | 状态 |
|---|---|---|
| `layers[]` 顺序 / `z` | `Layer` 列表顺序、`is_kv` 置顶思路 | ✅ 已有 |
| `blend` | `Layer.blend`（7 种） | ✅ 已有 |
| `opacity` | `Layer.opacity` | ✅ 已有 |
| `xform.scale/x/y` | `Layer.img_scale` / `img_x` / `img_y` | ✅ 已有 |
| `speed` | `Layer.speed`（钳位 0.1~3.0） | ✅ 已有 |
| `trans_*` | `kv_trans_kind`：`fade / cut / slide / zoom / glitch` | ✅ 已有 5 种 |
| **`crop`** | — | ❌ **需新增**（`MediaItem` 无此字段） |
| **`src_in_sec / src_out_sec`** | — | ❌ **需新增**（素材入出点） |

> ⚠ 上表最后两行是**真正的新工程量**。其余全部是"把已有能力搬进码表"。

### 4.3 版本与能力协商（向下兼容）

导入时按顺序判定，**一律不阻断**：

1. **`format_version` > 本版支持** → *"这张码表来自更新版本的工具（格式 v3，本版支持 v1），部分内容可能读不到，已按 v1 尽力读取。"*
2. **`min_app_version` > 当前版本** → 强提示 *"要求 v2026.10.01.00 以上，当前 v2026.09.27.09，部分画面可能不对。"* → 允许导入，**只读，不提供回存**。
3. **`requires_features` 有本版不认识的能力** → 列清单 *"以下能力本版没有，将被忽略：clip_crop、trans_glitch"*。
4. **缺素材** → *"有 3 个视频没找到"* → 可选：**占位色块先跑** / 手动指定路径。（UI 表现见 §15）
5. **曲目匹配不上** → 列出未匹配清单 → **人工指认一次**，结果存进本地映射表。

**v1 能力词表**（`requires_features`）：`layer_multi`、`clip_crop`、`clip_speed`、`clip_inout`、`trans_glitch`、`trans_zoom`、`video_embed`、`remote_source`(预留)。
> ⚠ **只增不改不删**；废弃项保留在词表里标 deprecated。

### 4.4 ★ 五个版本号，各管各的（绝不能绑死）

| 名字 | 是什么 | 谁决定 | 什么时候变 |
|---|---|---|---|
| **程序版本** | `2026.09.27.09` | 主程序打包时自动生成（`src/_build_ver.py`） | 每次打包 |
| **编辑器版本** | `1.0.0` | 编辑器自己维护 | 编辑器发版 |
| **格式版本** `format_version` | 文件结构版本（整数） | 我们手工定 | **只有文件结构变了才 +1**（极少，可能一年一次） |
| **最低要求** `min_app_version` | 这张码表需要主程序 ≥ 某版本 | **编辑器自动算** | 用到新能力就抬高 |
| `generator` | 记录"谁在什么系统上导出的" | 导出时写入 | 仅用于排查问题 |

⚠ **核心原则**：程序版本天天变，格式版本几乎不变。**用程序版本号当格式版本是设计错误** ——
否则每次发版都会让所有旧码表被误判为"旧格式"。

## 5. 位置源（Position Source）抽象层

### 5.1 接口

```python
# src/position_source.py
class SourceStatus:
    state: str        # "absent" | "probing" | "connected" | "degraded" | "blocked"
    detail: str
    last_update: float

class DeckState:
    deck: int
    is_playing: bool
    position_beats: float | None   # ★ 首选：相对曲首的拍数（免疫变速）
    position_sec: float | None     # 兜底
    position_kind: str             # "beats" | "orig_sec" | "wall_sec"  ← 决定要不要乘速率 r
    bpm: float | None
    key: str | None
    title: str | None
    artist: str | None
    duration_sec: float | None
    is_audible: bool               # 哪个 deck 真的在被听到（VDJ 能给！）
    confidence: float
    source_clock: float            # 本机单调时钟，用于延迟补偿

class PositionSource:
    name: str
    priority: int
    def probe(self, timeout: float = 2.0) -> tuple[bool, str]:
        """只探测「能不能用」，不建立连接。"""
    def start(self, on_state) -> bool:
        """真正建立并订阅。on_state 由适配器在后台线程回调。"""
    def stop(self) -> None: ...
    def status(self) -> SourceStatus: ...
```

> ⚠ **项目铁律**：「探测能力」与「真正建立」**必须是两个函数**（NDI 那个坑就是这么来的）。
> ⚠ **回调必须节流**：回调里**只更新一份最新快照**，引擎每帧读最新值 ——
> **绝不把高频回调直接接进 Qt 信号**（违反"跨线程只投递轻量信号"的铁律）。

### 5.2 各适配器要点与发现机制

| 适配器 | 发现方式 | 能拿到 | 前置条件 |
|---|---|---|---|
| **vdj**（★ P1 先做） | 见下方三条通路 | 见下方 | VDJ 2023+ Pro（Network Control）/ 任何版（History） |
| **pioneer**（Pro DJ Link） | 加入局域网监听 UDP **50000** 广播 | 曲名/艺术家/专辑/BPM/**调性**/封面/**beat position + phrase**/**热指示**/on-air/tempo master/波形 | **有线千兆网 + 同子网**；需占 50000 端口 |
| **denon**（StageLinQ） | **mDNS** `_stagelinq._tcp` | 曲名/艺术家/专辑/BPM/调性/播放状态/fader/**beat position + timeline**/封面 | 同一局域网 |
| **serato** | 它主动连回来（本机起监听） | 曲名/艺术家/BPM/封面/deck/**播放头**/on-air/fader | **必须同一台电脑** |
| **relay**（互联网中继） | 我方中继服务器（见 §10） | 由小助手决定（最好含 position） | 需中继服务 |
| **sim**（模拟） | 无需发现，UI 上给滑块 | 全部字段可控 | **仅开发/自测，不对用户暴露** |

#### 5.2.1 ★ VirtualDJ 的三条通路（已查证，P1 就做它）

| 通路 | 怎么开 | 能拿到 | 更新速度 | 优 / 劣 |
|---|---|---|---|---|
| **① OSC（原生）** | 设置里设 `oscPort`（**需 VDJ PRO 授权**） | `/vdj/query/{vdjscript}` 查询；**`/vdj/subscribe/{vdjscript}` 参数变化时主动推送**（如 `/vdj/subscribe/deck/1/get_bpm`）；命令如 `/vdj/deck/1/play` | **最快，事件驱动** | 优：原生、可订阅、亚秒级；劣：⚠ **bool 状态查不到**（论坛实测 `/vdj/query/deck/1/play` 取不到），所以"是否在播"要靠别的字段推断 |
| **② Network Control 插件（HTTP）** | Config → Extensions → 装 **Network Control**，**再去 Master Effect → Auto-Start 启用**（⚠ 只装不启用无效），默认端口 **8080** | 4 个 deck 的 title/artist/album/genre/**key**/**BPM（原始，不受 pitch 影响）**/file path/deck number/**`is_audible`** | 亚秒级（轮询 1s 足够） | 优：**字段最全 + 能给"哪个 deck 真在被听到"**；劣：要装插件并手动启用 |
| **③ History M3U 文件** | 设置 `writeHistory=Yes` → `%LOCALAPPDATA%\VirtualDJ\History\*.m3u` | 曲名/艺术家/时长/文件路径 | ❌ **播放后才写，没有实时位置** | 优：所有版本可用、零配置；劣：**只能算"认歌"，不能算位置源** |

**结论**：P1 用 **① + ②**（OSC 订阅拿节拍级变化，Network Control 拿全字段与" audible deck"），**③ 作为保底认歌**。

**顺带发现**：VDJ 还有 **OS2L（Open Sound To Light）** —— 官方专门用来**把 beats 和 bpm 发给灯光/DMX 软件**（`os2l` / `os2lDirectIp` / `os2lBeatOffset`）。虽然我们不做灯光，但**这条是官方支持的"对外同步"通道**，将来若要做"给别人同步"可以用。

#### 5.2.2 为什么 djay 不做（v1）

- djay Pro for Windows 是 **Microsoft Store 的 UWP 应用**（沙箱）⇒ 读它的文件 / 进程间通信都受限；
- 官方**没有对外状态 API**；能用的只有 **MIDI 输出**（控制器 LED 反馈）和 **Ableton Link**（只有节拍，没有曲目/位置）；
- ⇒ **工作量高、收益低，v1 不做**。（如果将来必须支持，走"MIDI 反馈 + 用户手工映射"这条最差但唯一的路。）

### 5.3 仲裁与降级

```
选择顺序：
1. 用户手动锁定某一家（设置里"只监听 X"）              ← 最高优先
2. 候选 = 所有 state == connected 的源
3. 优先「is_playing 且 position 有效」的；有 is_audible 时优先 audible
4. 仍多个 → 按 priority，再按 last_update 最新
5. 一个都没有 → 码表图层进入「待机」：不显示、不干预，退回现有自动切换
```

**降级链**：`connected → degraded（尝试用最后已知状态，超时后停用）→ blocked（本场不再重试）`。
⚠ 参考 GPU 那套（`degraded` 后冷却再放开一次真实探测），**不要写成"每帧重试"**。

### 5.4 铁律

1. **全部探测 / 监听在后台线程**，主线程绝不碰。
2. **失败绝不影响演出**：接不到 → 退回自动切换，不黑屏、不弹模态框、不阻塞。
3. **绝不对设备做写操作**（不遥控、不加载曲目）—— 只读。
4. **端口冲突要能优雅退出**：Pro DJ Link 需 UDP 50000（可能被 rekordbox 占）、VDJ Network Control 需 8080
   → 先试绑定，失败报 `blocked` 并说清原因。
5. **本机时钟为准**：时间戳一律 `time.monotonic()`，绝不用墙钟。

## 6. 曲目识别（三级匹配）

```
① 指纹匹配（最可靠）—— VJ 端有该曲音频 → 复用现有 fp.py
② 元数据匹配 —— normalize(artist)+normalize(title)，强约束 |duration 差| ≤ 2 秒
③ 文件名匹配 —— basename 归一化
④ 全失败 → 界面列「未匹配」清单（显示"正在放的：《X》-《Y》 3:12"）→ 人工指认一次 → 存入
   cfg["cuesheet"]["track_map"]，下次自动命中
```

> ⚠⚠ **关于"重复段落"的疑问（用户提出，担心得对但不会成为问题）**
>
> 用户担心："一首里有两大段完全一样，一个后面接 drop、一个后面接 breakdown，指纹不会搞混吗？"
>
> **答案：认歌和定位是两件事。**
> - **认歌（指纹）** 只需要判定"这是哪首歌" —— 整首歌就是这一首，重复段落不影响判定。
> - **位置（播到第几秒）** 来自**设备本身**（VDJ / 碟机自己知道），**是权威的、唯一的**。
> ⇒ 所以"两段一样但后面不同"**不会出问题**。
>
> ⚠ 但**有一种情况会出问题**：**完全没有位置源时**，我们想用"音频指纹反推播到哪了"
> （现有节拍网格的 `recognized_offset` 就是干这个的）—— 那时**重复段落确实会骗人**
> （我们已实测踩过：`Can We Believe That` 锁到了重复副本，误锁 54 秒）。
> ⇒ **规则**：位置一律以位置源为准；**只有完全无位置源时才允许音频推断**，
> 且必须用连续性提示（`fp.match(hint_delta=)`）并在界面上明确显示"位置推断中（可能不准）"。

⚠ **匹配错的代价比匹配不上更高**（会放错画面）⇒ **模糊时一律走人工**。

## 7. 码表图层（引擎侧集成）

### 7.1 `Layer` 扩展

```python
self.is_cuesheet = False    # 码表图层
self.cuesheet_id = ""       # 绑定的码表 id（存 cfg["cuesheets"]）
self.cs_fade = {}           # {lyr_id: 当前过渡进度}
self.cs_state = "idle"      # idle / waiting / active
```

`to_dict()` 需同步；旧配置读不到这两个字段时用 `getattr(..., False)` 兜底。

### 7.2 ★ 启用开关 = 图层自己的小眼睛

```
if not layer.visible:          → 完全不检测、不触发（连位置源都不订阅）
if not layer.is_cuesheet:      → 普通图层，照旧
if 位置源未就绪 / 曲目未匹配 / 无生效片段 → 该图层退回普通图层行为（不黑屏、不空窗）
else                        → 接管
```

| 现有机制 | 码表图层「激活」时 |
|---|---|
| 自动模式 / 逐拍交替 / 档位切换 / `next_scene` | **排除**（与 Kv 同一套排除思路） |
| 节拍网格（八拍乐句） | **保留**：片段可吸附小节/乐句头，共用坐标系 |
| Kv 待机层 | **共存**：码表负责"有歌时"，Kv 仍负责静音时段 |
| 后处理 / 颜色 | **正常作用**（不像 Kv 那样跳过） |

### 7.3 触发与过渡

```
每帧（引擎 tick）：
  1. 读位置源最新快照（O(1)）
  2. 算"相对曲首的拍位" pos_beats：
       position_kind == "beats"    → 直接用
       position_kind == "orig_sec" → pos / beat_len
       position_kind == "wall_sec" → pos / beat_len / r      ← ⚠ 别忘 r（变速）
  3. 对每个层，找最后一个 at_beats <= pos_beats 且未结束的片段
  4. 片段变化 → 用该片段自己的 trans_in / trans_out（fade/cut/slide/zoom/glitch）
  5. 曲终 → 各层按各自 trans_out 淡出
```

⚠ **回滞**：片段边界附近加 **0.15 拍**回滞，否则位置抖动会来回触发。
⚠ **seek / loop 容错**：位置突然倒退或大幅前跳（> 2 小节）→ **直接把当前片段重算，不做过渡**
（DJ 打了 loop 就该立刻跟上，慢慢淡入反而更难看）。

## 10. 三种拓扑（同机 / 局域网 / 互联网）

| 场景 | 发送方 | 我们怎么接 | 延迟 |
|---|---|---|---|
| **① 同机**（VDJ / djay 在你这台电脑上） | 软件自己 | 本机直读：VDJ OSC（订阅）/ Network Control（HTTP:8080） | **< 100 ms** |
| **② 局域网**（DJ 用另一台电脑或碟机） | 那台装**小助手**；或碟机直接广播 | 我们监听局域网（Pro DJ Link / StageLinQ / 小助手的 UDP 广播） | < 100 ms |
| **③ 互联网**（远程 DJ） | 小助手 → **TLS WebSocket** → 我方**中继服务器** | 我们从公网连中继 | 50 ~ 300 ms |

**关键点**
- ⚠ **中继服务器必须由我们提供** —— 对方家里通常没有公网 IP，直连不可行。
- ⚠ **必须做时钟对齐**，否则画面比声音慢一截：
  小助手每 100ms 发 `{track_key, position_beats|position_sec, position_kind, sender_monotonic_ms, sequence}`；
  我们按 `到达时刻 - 平滑后的单向延迟` 推算真实进度；用指数滑动平均估延迟；**补偿上限 300ms**
  （抖动过大就直接"到达即当前"，宁愿准也不要飘）。
- 延迟 > 300ms 时**降级为"曲目级"触发**（只保证对歌，不追求精确拍到）。

**小助手的形态**：独立 exe（Python 打包）—— 读本机 VDJ/碟机状态并转发。⚠ 网页版做不了本机协议。

## 13. 风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| 逆向协议随版本失效 | 位置源突然不可用 | 能力探测 + `degraded/blocked` + 绝不影响演出 |
| **无位置源时用音频推断位置** | **重复段落会骗人**（已实测踩过） | 位置以设备为权威；音频推断只作兜底 + 界面明示"可能不准" |
| 设备状态刷新 100~300ms 延迟 | 画面比声音晚 | 过渡时长留余量；**不做 < 100ms 的精确打击**；必要时用预测 |
| 位置抖动 / loop / 变速 | 片段反复触发或错位 | 0.15 拍回滞；`position_kind` 区分是否乘 r；大跳变直接重算不做过渡 |

| VDJ Network Control 只装不启用无效 | 用户以为开了其实没开 | 探测时给明确提示；文档写清"要去 Master Effect → Auto-Start 启用" |
| 端口冲突（50000 / 8080） | 探测失败 | 先试绑定再报 `blocked` + 说清原因 |
| djay（UWP 沙箱） | 想支持但没接口 | v1 明确不做，文档写清原因 |
| **crop / 入出点 是新引擎能力** | 工期低估 | 单列 P0.5，不混进 P0 |
| macOS 打包 | 编辑器上线晚 | 后置，v1 只做 Windows |
| 新依赖许可 | 影响发行 | 只用 **MIT**（`alphatheta-connect` / `stagelinq`）；写进 `NOTICE.md`。⚠ 现有 Discogs-EffNet 的 CC BY-NC-SA 非商业限制不变 |
| 匹配错曲目 | 放错画面（比不放更糟） | 模糊一律走人工确认 |
